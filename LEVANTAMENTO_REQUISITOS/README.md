# 📚 Engenharia de Software: Levantamento de Requisitos

## 📑 1. Conteúdo de Aula
*   **Introdução:** Definição de requisitos e importância no ciclo de vida do software.
*   **Processo de Engenharia:** Elicitação, análise, especificação, validação e gerenciamento.
*   **Objetivo:** Compreender as reais necessidades do cliente para evitar retrabalho e falhas no projeto.

---

## ⚙️ 2. Requisitos Funcionais e Não Funcionais

### Requisitos Funcionais (RF)
*   **Definição:** O que o sistema deve fazer (funções e comportamentos).
*   **Exemplos:**
    *   **RF01:** O sistema deve permitir o cadastro de novos usuários.
    *   **RF02:** O sistema deve emitir um comprovante após a confirmação do pagamento.

### Requisitos Não Funcionais (RNF)
*   **Definição:** Como o sistema deve fazer (qualidade, restrições e propriedades).
*   **Exemplos:**
    *   **RNF01:** A página de login deve ser carregada em menos de 2 segundos.
    *   **RNF02:** O sistema deve ser criptografado utilizando o padrão AES-256.

---

## 📊 3. Diagramas na Engenharia de Requisitos
*   **Casos de Uso (UML):** Representam as interações entre os atores e o sistema.
*   **Elementos Principais:**
    *   **Atores:** Usuários ou sistemas externos.
    *   **Casos de Uso:** Funcionalidades representadas por elipses.
    *   **Associações:** Linhas que conectam atores aos casos de uso.
*   **Diagrama de Fluxo de Dados (DFD):** Mapeia o caminho da informação dentro do sistema.

---

## 📝 4. Relatórios Técnicos
*   **Documento de Especificação de Requisitos (SRS):** O registro oficial de tudo o que será desenvolvido.
*   **Estrutura Básica:**
    1.  Introdução e Escopo do Projeto.
    2.  Descrição Geral do Sistema.
    3.  Lista de Requisitos Funcionais e Não Funcionais.
    4.  Modelos de Análise (Diagramas).
*   **Importância:** Serve como contrato técnico entre a equipe de desenvolvimento e o cliente.

---

## 💡 5. Técnicas de Elicitação: Brainstorm
*   **Conceito:** Reunião livre de ideias com a equipe do projeto e stakeholders.
*   **Fases do Processo:**
    1.  **Geração:** Foco na quantidade de ideias, sem julgamentos ou críticas.
    2.  **Triagem:** Organização, agrupamento e filtragem das ideias mais viáveis.
*   **Vantagem:** Estimula a criatividade e revela requisitos ocultos ou inovadores.

---

## 🎨 6. Técnicas de Elicitação: Prototipagem
*   **Conceito:** Criação de modelos visuais do sistema antes do desenvolvimento real.
*   **Tipos de Protótipos:**
    *   **Baixa Fidelidade:** Desenhos em papel ou wireframes simples (foco no fluxo).
    *   **Alta Fidelidade:** Telas interativas e clicáveis (foco no design e experiência).
*   **Vantagem:** Validação rápida de ideias e interface com o usuário final.

---

## 🗣️ 7. Técnicas de Elicitação: Entrevistas
*   **Conceito:** Conversa direta e estruturada com os usuários e donos do negócio.
*   **Formatos:**
    *   **Fechadas:** Perguntas com respostas diretas ou de múltipla escolha.
    *   **Abertas:** Perguntas dissertativas que permitem ao entrevistado explicar processos.
*   **Dica Prática:** Prepare um roteiro prévio, mas mantenha flexibilidade para explorar novos pontos.
